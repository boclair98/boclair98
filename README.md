## About Me

Java와 Spring Boot를 중심으로 REST API, 인증·인가, 데이터 조회 흐름, 비즈니스 로직을 구현합니다.

단순히 기능을 완성하는 것보다 사용자가 어떤 맥락에서 서비스를 쓰는지, 데이터가 어떤 상태로 흘러야 안전한지, 이후 변경이 들어왔을 때 구조가 버틸 수 있는지를 함께 봅니다. Controller, Service, Repository의 책임을 나누고 트랜잭션 경계와 데이터 일관성을 고려하는 개발을 지향합니다.

최근에는 약속 장소 추천, 날씨 기반 메일 발송, 면접 시뮬레이션처럼 실제 사용자 흐름이 있는 서비스를 만들며 백엔드 설계와 제품 경험 사이의 연결을 연습하고 있습니다. 공부하면서 막혔던 부분, 직접 실행해 확인한 결과, 다시 찾아볼 개념은 [기술 블로그](https://boclair98.tistory.com/)에 꾸준히 정리하고 있습니다.

### What I Care About

- 사용자가 막히지 않는 자연스러운 서비스 흐름
- 도메인 규칙이 코드 안에서 분명하게 드러나는 구조
- Controller, Service, Repository 사이의 명확한 책임 분리
- JPA, Querydsl, SQL을 활용한 안정적인 데이터 조회와 변경
- 트랜잭션 경계와 데이터 일관성을 고려한 비즈니스 로직
- 인증, 권한, 상태 관리처럼 서비스 신뢰도에 직접 연결되는 영역
- 오류의 원인을 재현하고 기록해 같은 문제를 반복하지 않는 습관
- 작게 만들고, 직접 확인하고, 개선 과정을 기록하는 개발 방식

## Product Projects

### 1. [MeetPlace](https://github.com/boclair98/MeetPlace)

여러 명이 만날 때 참가자의 출발지와 원하는 장소 카테고리를 기준으로 실제 약속 장소를 추천하는 Spring Boot 웹 서비스입니다. 단순히 지도상의 중앙값을 보여주는 것이 아니라, 각 참가자의 이동 부담과 장소의 신뢰도를 함께 고려한 결과를 제공하는 데 집중했습니다.

**주요 구현 내용**

- 참가자별 출발 좌표를 기반으로 중간 지점 계산
- Kakao Local API를 활용한 장소 검색 및 위치 정보 연동
- Google Places API를 활용한 장소 정보와 리뷰 데이터 보강
- 평균 이동거리, 거리 편차, 리뷰 신뢰도를 반영한 추천 점수 설계
- 장소 카테고리와 사용자 조건에 따른 추천 후보 필터링
- 결과 탭, 거리 비교, 장소 상세 정보 및 공유 문구 생성
- 사용자가 출발지를 입력하고 결과를 비교하기까지의 흐름을 중심으로 UI 구현

**배운 점**

- 여러 외부 API의 응답 구조를 하나의 서비스 데이터로 정리하는 방법
- 거리와 리뷰처럼 성격이 다른 값을 추천 점수로 조합하는 과정
- 정확한 계산뿐 아니라 사용자가 결과를 이해하고 선택할 수 있는 설명 방식의 중요성

### 2. [Weather](https://github.com/boclair98/Weather)

지역별 날씨 정보를 조회하고, 구독자에게 필요한 날씨 정보를 맞춤형 메일로 발송하는 서비스입니다. 외부 API 호출부터 구독자 관리, 메일 생성과 발송까지 이어지는 백엔드 처리 흐름을 구현했습니다.

**주요 구현 내용**

- 날씨 API 연동 및 지역별 날씨 데이터 조회
- 지역을 기준으로 한 구독자 정보 저장과 관리
- JavaMailSender 기반 맞춤형 메일 생성 및 발송 기능 구현
- `@Async`를 활용한 비동기 메일 발송 구조 적용
- 메일 발송 실패와 외부 API 오류를 고려한 예외 흐름 설계
- 구독자 증가 상황을 고려한 Queue 및 Batch 방식의 개선 방향 설계

**배운 점**

- 외부 API 장애가 내부 서비스 흐름에 미치는 영향을 줄이는 방법
- 요청 처리와 시간이 오래 걸리는 메일 발송 작업을 분리하는 이유
- 데이터가 많아질 때 단건 처리에서 배치·큐 방식으로 확장해야 하는 기준

### 3. [Question](https://github.com/boclair98/Question)

직무에 맞는 면접 질문을 제공하고 제한 시간 동안 답변을 연습할 수 있도록 만든 Spring Boot 기반 면접 시뮬레이션 서비스입니다. 질문 제공 기능뿐 아니라 인증, 조회, 커뮤니티 데이터 구조까지 함께 설계했습니다.

**주요 구현 내용**

- 직무별 면접 질문 제공 및 40초 응답 타이머 구현
- Spring Security와 JWT를 활용한 인증·인가 구조 설계
- Querydsl 기반 조건별 동적 조회 기능 구현
- 프론트엔드에서 사용할 수 있는 REST API 설계
- 사용자와 질문, 면접 기록 사이의 관계를 고려한 데이터 모델 구성
- 면접 경험과 정보를 공유하기 위한 커뮤니티형 데이터 구조 설계
- 인증 실패, 권한 부족, 잘못된 요청을 구분하는 예외 처리

**배운 점**

- 인증 정보가 필요한 요청에서 사용자 식별과 권한을 처리하는 흐름
- 조회 조건이 늘어날 때 Querydsl로 쿼리를 구성하는 방법
- 화면 기능을 구현하기 전에 API와 데이터 관계를 먼저 정리하는 중요성
